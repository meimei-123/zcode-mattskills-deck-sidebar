# GitHub 后端:整体克隆上游房间、显式启用、仓库只从项目根解析

**Status:** accepted · 2026-11-26

0.6.1 的看板只认本地 `.scratch/`。本插件自己的仓库、上游的票与讨论都在 GitHub Issues 上,这些项目在 ZCode 里打开时看板要么空着、要么只能让 agent 手敲 `gh`。上游 DSH deck 的 GitHub 房间已经把议题的读、写、计数、子议题、阻塞边、仓库权限做完了(24 条契约操作里 GitHub 提供 23 条),本仓要做的是把它搬进来,并让 `deck_*` 工具按活动项目的后端分发。四条取舍记在这里:为什么整体克隆而不重写、为什么显式启用而不按远端自动识别、为什么仓库只从活动项目根解析、为什么不做上游的额度账本与冷却窗口。

## 决定与取舍

### 一、整体克隆房间,不重写

按 ADR-0002 的 a′ 边界再走一遍:**搬**上游 `src/tracker/rooms/github` 的整张 TS 依赖图(构建期从上游只读树读入,esbuild 打成 `dist/github-room.mjs`,外部说明符只有 `node:*`,没有 npm 依赖);**新写**的只有三样:Node 服务垫片(与版本管理页共用 `src/node-shims.mjs`)、构建胶水(`build-github.mjs`)、服务端的装配与按后端分发(`src/github/`)。

重写被否的理由和 ADR-0002 同一条:议题归一、分页游标、限流档位、权限判定、错误分档这些细节只有逐行读上游才能保真,重写等于伪装的移植,而且上游一升级就对不上。克隆的代价是房间的错误原文带着上游口径(会提到 DSH 与 `DSH_GH_PATH`),所以工具的人话摘要由本仓自己写,原文原样放进结构化回包的明细,不改上游一个字。

### 二、显式启用,不按远端地址自动识别

上游的判定顺序是「手选 > 声明 > 自动识别」,远端指向 github.com 就判 GitHub。本仓去掉自动识别,只认:本会话手选 > 锚文件(`docs/agents/issue-tracker.md` 的一级标题)> 默认本地 Markdown。

两条理由。一是本地 Markdown 是既成默认:已有本地看板的项目多半也在 GitHub 上,自动识别会把它们翻到议题侧,升级就打乱了现有用法。二是信任边界:插件不该在用户没点名某个仓库时,带着用户的 gh 登录态向它出站。代价是 GitHub 用户要多一步;兜底是后端 chip 的提示位(远端在 GitHub 上时显示「可以切到 GitHub 议题」)、一键切换,以及「让 agent 写进锚文件」把这次选择留下来。

### 三、仓库只从活动项目根解析

工具不接受仓库参数。仓库身份从活动项目根自己的 `.git` 解析,三层兜底:git 远端、`.git/config`、`gh repo view`;前两层纯本地、不出站,并且用 `<root>/.git` 的存在性与 `GIT_CEILING_DIRECTORIES` 双重锚定,不让 git 往上发现父目录的远端(仓库内的测试夹具、普通子目录不该继承父仓的仓库身份)。

理由与 ADR-0002 的 `deck_git` 路径边界同源:`deck_*` 工具对 agent 可见,不能变成对任意仓库的 gh 执行器。项目根解析不出仓库时,读工具回人话错误,写工具一个字不发。写权限同样收在项目根上:第一次写入前问一次仓库权限,既不能推也不能整理就按只读处理,拒绝全部写操作并说明;问不出来按未知处理,交给远端裁决。

### 四、不做额度账本与冷却窗口

上游出站控制面有五样本事:拿名额、认取消、记写、报通路失败、报成功;上游的额度账本(插件最多占剩余额度的一定比例、黄红两档降速)与并发名额闸都挂在这套形状上。本仓接直通实现:拿名额立即放行,不排队、没有冷却窗口,记写是空操作,但五样本事一件不少——缺一件房间就一条命令都不发,这个形状保留。

理由是场景不同:本仓是单会话单消费者,一个 ZCode 进程里一块面板;上游的账本是给多会话宿主防互相挤兑用的,搬进来只是多一份没有消费方的状态。省掉账本不等于不限速:变更探测在服务端按项目根限速(距上次探测不到 60 秒不出站,间隔 `ZCODE_GITHUB_PROBE_MS` 可调,连续失败加倍放慢,上限 5 分钟),面板切到后台停止探测,只有回到前台与「重新检查」才强制探一次。代价是长时间高频写的工作流会比上游更快消耗小时额度。

## Consequences

- 本地 Markdown 的工具回包与 0.6.1 逐字一致,唯一例外是 `deck_project_list` / `deck_project_use` 的 `active` 多一块 `backend`;这条由 `test/markdown-frozen.test.mjs` 的黄金对照守(17 条调用,除 `active.backend` 外一个字符都不许差)。
- 面板的分叉只在头部:后端 chip 与它的跟随逻辑(后端 id 变了整体重取、清导航与详情缓存)。上游的列表、详情、地图详情页、技能页、版本管理页、动作模板零改动。
- 上游升级时:重跑 `node build.mjs` 重新克隆房间,按文件对账;房间错误原文里的 DSH 字样不动,人话摘要另写。
- 新增的后端只有 markdown 与 github 两种;GitLab 按本地 Markdown 显示并在 chip 里说明,不做出站探测。
- 只读仓库:看板照常能看,写操作被拒并说明是只读,一条写命令都不发。
- 本版不做:按远端地址自动识别、拉取请求页签、建仓向导、标签配色弹窗、两种后端之间的票迁移、上游的额度账本与冷却窗口、GitHub Enterprise 主机的走查。评论分页只翻到前 200 条,列表整表最多 500 张,到上限标 `partial`。
- 未验证项留到真机走查(见 `SMOKE.md`):ZCode 的 MCP 服务进程里 PATH 有没有 gh(第一个确认点),议题链接能不能在 ZCode 的 webview 里开新窗口。
